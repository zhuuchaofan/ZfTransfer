# Zf 传图 iOS 版（有线，试验中）

用 USB-C 线连接 Nikon Zf 和 iPhone，浏览相机里的照片，把 JPEG 原图导入相册。读取相机用的是苹果的 ImageCaptureCore 框架，没有用 Android 版的 PTP/IP 代码。

当前状态：**代码写完，还没在 Mac 上编译过，也没有连过相机。** 第一次编译很可能要改一些错误。

## 目录

- `ZfCore/`：纯逻辑的 Swift 包，从 Android 版移植：目录整理、双卡副本合并、格式和导入状态筛选、日期分组、自动导入规则。不依赖 iOS，可以在 Mac 或 Linux 上跑测试。
- `App/`：iOS 应用（SwiftUI）。
  - `CameraLink.swift`：发现相机、打开会话、读目录、缩略图、下载原图。
  - `ImportStore.swift`：保存到相册和导入记录。
  - `Importer.swift`：批量导入。
  - `GalleryView.swift`、`PreviewView.swift`、`ContentView.swift`：界面。
  - `DiagnosticLog.swift`：应用内诊断日志，右上角按钮打开，可以复制。

## 在 Mac 上运行

需要：Xcode 16 或更新版本（iOS 27 的 iPhone 需要能支持它的 Xcode）、iPhone 15 Pro、苹果账号（免费的个人账号就行）。

1. 打开 `ios/App/ZfTransfer.xcodeproj`。
2. 左侧点工程 → TARGETS 选 ZfTransfer → Signing & Capabilities：Team 选你的苹果账号。如果提示 Bundle Identifier 不可用，把 `com.xiaozhu.zftransfer.ios` 改成别的，比如加上你的名字。
3. iPhone 用线连 Mac，在 iPhone 的“设置 → 隐私与安全性 → 开发者模式”里打开开发者模式（第一次需要重启）。
4. Xcode 顶部选你的 iPhone，按 ⌘R 运行。第一次运行要在 iPhone 的“设置 → 通用 → VPN 与设备管理”里信任你的开发者证书。
5. 免费账号签的应用 7 天后会失效，到时重新运行一次。

只跑纯逻辑测试：

```bash
cd ios/ZfCore && swift test
```

## 实机测试清单

先做第 0 步，不需要本应用。

0. Zf 的 USB 设置改成 MTP/PTP（菜单名称以相机为准），用 C 对 C 的线连 iPhone，看系统“照片”应用能不能列出和导入 Zf 里的照片。记下结果。
1. 打开本应用，看是否出现权限弹窗、是否显示“正在读取照片列表”，最后出现照片网格。如果系统“照片”抢先弹出导入界面，先关掉它。
2. 照片数量与相机里的是否一致（顶部有统计）；双卡备份时同一张是否只显示一次；存储卡筛选是否出现。
3. 缩略图是否都能出来，滚动是否流畅。
4. 点一张 JPEG 预览：多久出来，能否缩放。
5. 选几张导入：相册里是否出现、文件大小和拍摄时间是否正确、“已导入”标记是否出现。
6. 导入过程中拔线，应用是否给出失败提示而不是卡住；重新插上能否继续。
7. 打开诊断日志，点“复制”，把内容发回来。日志里只有事件和数量，没有照片内容。

## 已知限制和没有验证的地方

- 只能有线；没有无线传输，也没有后台导入。
- 存储卡的区分方式（按顶层文件夹）是推测的，要看实机日志确认。
- 拍摄时间用的是 ImageCaptureCore 报告的文件创建时间，按手机时区格式化，可能和 Android 版读到的相机时间有差别。
- 苹果论坛有报告：iOS 26.1 测试版上读取相机内容的授权一直返回“未确定”。本应用只有在明确被拒时才停下，其他情况照常查找相机。
- “已导入”只依据本应用写入相册成功的记录，应用只申请“仅添加照片”权限，读不回相册。
